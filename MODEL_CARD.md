# EduNex synthetic academic-risk model v2.0.0

This is a reproducible demonstration of a predictive pipeline, not a validated model for real students. Staff review the transparent baseline and source evidence before any action. No automated adverse decisions are permitted.

## Data and outcome

Source: committed `data/processed/canonical_*_records.csv`, the synthetic Demonstration Institutional Dataset. The fixed-seed generator (`backend/scripts/generate_demo.py`, seed 42) produces academic profiles across four cumulative semesters. The label is **backlogs > 0 in semester t+1**, using the next academic-year/semester key. The generator makes backlog occurrence depend on synthetic CGPA; performance therefore reflects the generator's assumptions, not institutional generalization.

Features from semester t: CGPA, internal marks, existing backlogs, attendance, LMS logins, assignment completion, event/club/hackathon/certification counts, and student satisfaction. No names, IDs, departments, protected attributes, or future outcomes are model inputs. Current backlogs are distinct from next-semester backlogs. All domain joins include student, academic year and semester; duplicate keys fail. Missing complete-domain records are excluded and counted in the report.

## Evaluation protocol

Seed 42 partitions sorted student IDs into disjoint 60% training, 20% validation, 20% test groups. Training uses semesters 1/2 from 600 students (1,200 rows); validation and test each use semester 3 from 200 unseen students. Their labels come from semester 4. This combines forward-term evaluation with held-out students; it is not a pure temporal split of the same students. Semester 4→5 inference is extrapolation beyond the observed evaluation horizon.

StandardScaler and unweighted logistic regression fit training data only. Threshold is fixed at 0.5; no hyperparameter/threshold tuning occurs on validation or test. The deterministic comparator uses the existing academic-risk formula on the feature term only, including missing-signal renormalization and a MEDIUM threshold of 0.30 after dividing by 100. Its score is not a calibrated probability. Original baseline scales are preserved: the demo generator caps internal marks at 50 and LMS logins at 10, while baseline normalizers use 100 and 50. A constant training-prevalence comparator is also reported.

**Low recall is a material limitation:** the model detects only 4 of 23 positive test outcomes at its fixed threshold. Its ranking performance does not justify replacing the deterministic support queue. The baseline has higher recall/F1 here but substantially more false positives. No claim of universal superiority is made.

Calibration is checked using Brier loss and five equal-width probability bins, with counts and observed frequencies. The two highest bins contain one example each, so their estimates are highly uncertain. No post-hoc calibration is performed. Metric definitions follow [scikit-learn evaluation documentation](https://scikit-learn.org/stable/modules/model_evaluation.html) and [calibration documentation](https://scikit-learn.org/stable/modules/calibration.html).

## Inference and explanations

`academic_risk_v2.joblib` contains the fitted pipeline, exact feature contract, version, training-only background mean and evaluation report. Load only trusted local artifacts: joblib is executable serialization. Optional `EDUNEX_MODEL_PATH` selects another trusted v2 artifact. Missing/incompatible models use the transparent current-assessment baseline; the API explicitly returns a risk score without a probability field. Missing baseline inputs remain unavailable.

Each contribution is coefficient × (standardized feature − training background mean). Base log-odds plus all contributions reconstructs the prediction; a test checks this identity. Contributions explain model associations, not causes. Positive/negative/zero values mean higher/lower/neutral relative to training background.

## Reproduce and verify

From the repository root with dependencies installed and `.env` configured:

```powershell
.\.venv\Scripts\python.exe scripts/train_model.py
.\.venv\Scripts\python.exe -m pytest backend/tests/test_model_protocol.py backend/tests/test_ml.py -q --basetemp=.phase-work/pytest-model
```

Training reads committed synthetic CSVs and does not connect to the database. Existing legacy integration tests do use the configured synthetic PostgreSQL database. `--output`, `--report`, and `--data` allow independent reruns without overwriting the shipped artifact. In the same dependency environment, repeated runs produce identical reports and artifact hashes. Numerical/library changes across versions may alter results; reported versions make that visible.

## Fairness and intended use

Sensitive attributes are excluded, but engagement, attendance and digital activity can proxy unequal access, disability or disadvantage. Synthetic profiles cannot establish subgroup fairness or real-world validity. Before real use: consent/governance, institution-specific prospective validation, subgroup error audits, access controls, appeals, monitoring and staff training are required. No real PII belongs in this demonstration.
